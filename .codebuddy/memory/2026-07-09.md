## 修复 WorkBuddy 5.2.5 Linux 构建失败（apply-linux-patches.js）

**现象**：`make build-app` 在 5.2.5 / Electron 37.10.3 上因两个必需补丁锚点失配中止：
`required patches failed: updateRpcDisabled, networkDiagnosticsTimeouts`。

**根因**：
1. `updateRpcDisabled`：5.2.5 中 `registerUpdateHandlers(server, deps)` 改为
   `registerUpdateHandlers(registry, deps)`，且内部调用由 `handleRpc$1(server, ...)` 改为
   `require_workbuddy_auth_product_coordinator.handleRpc(registry, ...)`。
2. `networkDiagnosticsTimeouts`：网络诊断模块从 `main/index.js` 整体迁移到
   `main/seed-builtin-plugins.js`（`NetworkDiagnosticsService` 类）。patcher 只读 `main/index.js`，
   锚点必然找不到。

**修复**（仅改 `scripts/lib/apply-linux-patches.js`）：
- `updateRpcDisabled` 改为向后兼容：检测新签名 `registry` 后用
  `require_workbuddy_auth_product_coordinator.handleRpc(registry, ...)`，否则回退旧 `server`/`handleRpc$1`。
- 新增 `applyNetworkDiagnostics(s)` 复用函数；在 `assertRequiredPatches()` 前插入重定向块：
  若 `main/seed-builtin-plugins.js` 含诊断锚点，对其应用全套超时补丁并写回（repack 自动包含）。
  旧版 `main/index.js` 仍由原有块处理，保持兼容。

**验证**：`make build-app` 成功，`patch-report.json` 中 9 个 required 全为 true
（含 `updateRpcDisabled`、`networkDiagnosticsTimeouts`、`lydellPlatformPackageRegistered`）。

**次要/未处理**：10 个 optional 补丁在 5.2.5 失效（Fix 7 超时守卫 7A-7F、CLI 兼容等代码路径被上游重构），
均为 `markOptional` 按设计降级，不阻断构建。如需 Linux 稳定性兜底可后续补这些锚点。
